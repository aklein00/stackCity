# Stack City V2 — art direction document working outline

Status: outline. References are gathered; V2 artwork and UX implementation are not complete.

## 1. Brief and intended player experience

Teen audience, world-led premise, personal/business/societal lenses, learning question, and emotional promise.

## 2. Direction comparison

Sketchbook Botanicals; Wright-inspired City-States; Syd Mead Retro-Future. Show form, line, material, light, color, camera, interface, and teen-appeal hypotheses.

## 3. Reference interpretation

Name each work/creator and explain which quality informs which decision. Separate observation from proposed application.

## 4. Shape and composition

Silhouette, proportion, architectural rhythm, focal hierarchy, traversal/readability, and UI safe zones.

## 5. Environment applications

Room, garage/workshop, storefront, shared hub, and matched progression views. Mark drawings, generated studies, renders, and implemented scenes.

## 6. Object families

Useful props, recognizable function, upgrade grammar, materials, scale, and asset boundaries.

## 7. Color, material, and light

Calm decision surfaces, focal accents, celebration states, material families, and reproducible light/camera notes.

## 8. UI visual system

Typography, spacing, surfaces, icons, navigation, controls, finance labels, feedback, and component states.

## 9. UX reasoning

Goal → choice → preview → commitment → consequence → revision. Include alternate layouts, selected direction, observations, and changes.

## 10. Motion and feedback

Selection, confirmation, travel/transition if used, outcome, unlock, and reduced-motion intent. Distinguish designed motion from implemented animation.

## 11. Cohesion across experiences

What is shared, what varies, and how the persistent front door remains recognizable.

## 12. Cognitive load and accessibility

Information exposed per decision, readability at scale, focus, contrast, labels, and tested limits.

## 13. Original handmade work

Sketches, layout studies, material marks, object ideation, development, and annotations. Identify mixed-media inputs.

## 14. Production and extension

Reference-driven generation, blockouts, WorldFarm's bounded role, file/provenance tracking, revision effort, and a new-asset consistency test. LoRA training is not required.

## 15. Evaluation and recommendation

What each direction does well, its main unresolved issue, the next test, and the recommended direction if supported.

## 16. Supporting files and sources

Reference register, source files, native Figma links, manifests, process log, review records, and final delivery checklist.
