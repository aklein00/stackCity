# Scope and acceptance

## Objective

Demonstrate original environment/object art direction and crucial UI/UX skills for a teen personal-finance and entrepreneurship game universe.

## Proposed submission scope used for the estimate

- Three clearly differentiated visual directions.
- For each: one hero/storefront view, two supporting environment studies, one object family sheet, one key gameplay UI treatment, and concise usable rules.
- A recommended direction with one connected native Figma flow of approximately 5–7 primary views plus necessary decision states.
- A persistent-platform/front-door concept showing how experiences connect.
- A robust art direction document, approximately 20–30 designed pages or equivalent web sections, with supporting sources and files.
- Handmade evidence: approximately 9–12 environment thumbnails, 6–9 prop sketches, three UI ideation pages, and three more developed original studies. These are proposed targets, not quotas or completed work.
- A concise pitch, process evidence, actual tools/time record, and review/export package.

Do not interpret this as three complete games or three fully implemented prototypes.

## Acceptance

- Differences survive removal of color: form, composition, materials, line/rendering, and interface framing contribute.
- Financial decisions show commitments, consequence previews, feedback, and a revision/recovery path.
- Source reference, generated exploration, handmade work, and actual implementation are labeled honestly.
- A designer can use the rules to extend the world to another asset.
- Screens remain readable at the intended presentation and device sizes.
- Native Figma controls, flows, component states, and reviewed interactions demonstrate UX.
- Existing reference media is credited and linked.
- No claims of teen validation, mastered learning, production scalability, or tool performance without evidence.

## Scope exclusions

A full game, large city simulation, multiplayer, character production, rigging, a new WorldFarm studio implementation, LoRA training, and a comprehensive production asset library are outside the base estimate.

## Quality checkpoints

1. Agree on the learning question and comparable visual task.
2. Review the three shape/rendering/UI systems.
3. Choose which direction gets the deeper interaction proof.
4. Review handmade work and selected environment/object studies.
5. Validate the native Figma flow.
6. Finish the document, pitch, provenance, and rehearsal.

No fixed deadline or automatic approval is implied by these checkpoints.
